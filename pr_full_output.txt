### 2. **HIGH ÔÇö TUIC parser replacement is a behavioral regression and contradicts the committed specification**

`parsers/__init__.py` replaces the established `others.parse_tuic` with the new standalone implementation.

The previous parser:

- used default port `443`;

- does not implement the specified `max_idle_time` or `initial_max_streams` fields;
- swallows every exception without diagnostics.

This is not a compatible ÔÇ£extensionÔÇØ; it replaces a broader parser with a narrower and internally inconsistent one.

**Required correction:** preserve the established parser contract and normalization path, explicitly define any intended port migration, implement the fields/types in the committed spec, retain backward-compatible aliases, and add regression tests comparing old and new accepted URIs, malformed ports, oversized lines, IPv6, percent-encoded credentials, duplicate parameters, and all documented defaults.

### 3. **HIGH ÔÇö Hysteria3 implementation does not satisfy its own specification**

### 4. **HIGH ÔÇö Claimed HMAC steganography remediation is dead code; the ÔÇ£KATÔÇØ is not a KAT and the helper can hang forever**

### Verdict

More seriously, several headline security/features are implemented as disconnected helpers or tests that can pass without exercising production behavior.

I would not merge this as ÔÇ£complete remediation / 100% greenÔÇØ until the blockers below are resolved or the PR is honestly re-scoped and split.

## Critical / high-severity blockers

### 1. Laboratory chain testing still permits arbitrary outbound SSRF

`docs/LAB_CHAIN_TESTER_AUDIT.md` correctly identifies missing pre-execution outbound validation as **Critical** and proposes scanning every outbound `server` before invoking sing-box.

That remediation is absent. `src/configstream/testers/lab_chain_tester.py::test_chain_config()` still:

1. accepts an arbitrary client-supplied `config` dictionary,
2. calls `_ensure_config_ready()`,
3. serializes it,
4. launches sing-box.

`SecurityValidator` is used only to sanitize error text after execution. No code rejects loopback, RFC1918, link-local, metadata-service, IPv6-local, or suspicious internal destinations. A caller can therefore ask the backend tester to establish chains toward internal services such as `127.0.0.1`, private LAN hosts, or `169.254.169.254`.

**Required:** implement recursive outbound validation before process launch, validate hostnames after DNS resolution where applicable, constrain ports/types/detours, reject unknown outbound fields where practical, and add negative integration tests for IPv4, IPv6, encoded/local-hostname, and nested-chain cases.

### 2. Manifest signatures produced by the pipeline cannot verify under the validator

The signing track is internally incompatible:

- `Signer.sign_subscription()` signs `uint64(timestamp) || content_bytes`.
- `src/configstream/output/metadata.py::_attach_manifest_signature()` calls that method, but stores only `algorithm`, `signature`, and `key_id`; it does **not** store the timestamp.
- `scripts/validate_pages_artifact.py::_validate_manifest_signature()` verifies the signature against canonical manifest bytes **without** the timestamp prefix.

Therefore, when a signing key and verifier key are configured, the generated signature and validator payload differ byte-for-byte and verification must fail.

The new `src/configstream/signer.py::_canonical_manifest_payload()` helper is not wired into manifest generation or validation. `tests/unit/test_signer_canonical_replay.py` only proves that two dictionaries produce the same helper output; it does not generate, attach, serialize, reload, and verify a real manifest.

**Required:** define one versioned signature envelope and one canonical payload function used by both producer and verifier. Persist the signed timestamp (and ideally payload/schema version and key ID), enforce freshness consistently, then add a round-trip test using a generated Ed25519 keypair and the real manifest writer/validator.

### 3. The steganography HMAC migration does not affect the encoder or decoder

The PR description says pixel-offset scattering was upgraded to HMAC-SHA256. It was not.

Production embedding/extraction still uses `_derive_offsets()`, which computes raw `hashlib.sha256(prefix + key + salt + carrier_len)`. The PR adds a separate `derive_lsb_offsets()` HMAC helper at the bottom of `stego.py`, but no production call site uses it.

`tests/unit/transport/test_stego_kat.py` tests only this disconnected helper. It is also not a known-answer test: it compares the function with itself rather than asserting a fixed independently derived vector. Additionally, `derive_lsb_offsets()` can loop forever when `count > max_index`, because it requires unique indices but can never reach the requested count.

This directly contradicts `docs/STEGANOGRAPHY_SECURITY_REPORT.md` and `docs/STEGO_KAT_HMAC_SECURITY_AUDIT.md`, both of which say the real `_derive_offsets()` path must be migrated.

**Required:** replace or version the actual `_derive_offsets()` algorithm used by `_embed_permuted()` and extraction, define backward compatibility for existing v2 carriers, validate `count <= max_index`, and add fixed KAT vectors plus real pack/unpack compatibility tests.

### 4. WASM panic recovery was not implemented

The only PR change in `src/go/tester/wasm_main.go` is adding `hysteria3://` and `hy3://` to the recognized scheme list.

The pre-existing panic path remains flawed:

- `doTestProxy()` catches a panic in a deferred function but cannot convert it into a returned result.
- The Promise wrapper ignores `reject`.
- A panic can therefore be swallowed and the Promise resolved with an empty/nil result rather than a structured rejection.

This is exactly the failure documented in `docs/WASM_JS_BRIDGE_INTEROP_AUDIT.md`. The proposed reject-wrapper patch was not applied.

`tests/unit/test_wasm_panic_recovery.py` merely searches the Go source for the substring `recover()`. That substring existed in the defective implementation, so the test passes while proving nothing about Promise behavior.

**Required:** recover in the Promise goroutine, reject or resolve with a documented structured error exactly once, prevent double resolution, and execute the compiled WASM in a browser test that deliberately triggers the failure path.

### 5. Hysteria3 is not connected to normal pipeline ingestion

`parse_hysteria3` is exported from `configstream.parsers`, but `src/configstream/auto_detect.py` does not import or register it in:

- the scheme-to-parser map,
- fallback parsers,
- valid-scheme enforcement.

The pipeline calls `configstream.consumer.parse_config`, which forwards to `auto_detect_and_parse`. Consequently, normal source ingestion cannot parse `hy3://` or `hysteria3://` even though direct unit tests of `parse_hysteria3()` pass.

The alias is also absent from `_OUTPUT_PROTOCOL_ALIASES`, so `hy3` is not canonically normalized to `hysteria3` as claimed by `docs/protocol_matrix.json`.

**Required:** test the actual public ingestion entrypoint, not just the leaf parser. Add both schemes to auto-detection, fallback validation, canonical normalization, extraction/allowlists, frontend parsing where claimed, and protocol ordering where appropriate.

### 6. The new protocol parsers do not implement their own documented contracts

`docs/PARSER_EXTENSION_SPEC.md` specifies substantially richer behavior than the committed parsers.

For TUIC, the spec requires `cc_algo`, integer `max_idle_time`, integer `initial_max_streams`, and ALPN list semantics. The implementation only records `password`, `congestion_control`, and scalar `alpn`.

For Hysteria3, the spec requires `multi_port`, `obfs_v2`, `padding_len`, username/UUID mapping, and conditional rejection when an obfuscation mode requires a password. The implementation omits those fields and validations and leaves `uuid` empty.

The documents also disagree with each other: the extension specification advertises Sing-box and Clash export support for Hysteria3, while `docs/protocol_matrix.json` marks both exports false.

**Required:** establish one authoritative wire/field contract, implement it end-to-end, validate numeric/range/list fields, define malformed-input behavior, and regenerate all matrix/schema/wiki claims from that source of truth.

### 7. `GoBatchTester.test_custom_configs()` retains the unbounded IPC deadlock

The bridge audit explicitly scopes the bounded-drain remediation to both `test_batch()` and `test_custom_configs()`.

Only `test_batch()` now wraps `stdin.drain()` with a 15-second timeout. `test_custom_configs()` still acquires `_lock`, writes the payload, and awaits `proc.stdin.drain()` without any bound. A wedged daemon can still block this high-centrality bridge indefinitely while holding the process lock.

No new test exercises this method.

**Required:** use the same bounded write/drain policy for all IPC writers, clean pending futures, avoid holding the global lifecycle lock across a potentially slow drain, classify timeout/crash outcomes consistently, and test daemon restart/disable behavior for custom configs.

### 8. Internal source URLs can still leak through nested revived-proxy structures

The new `serialize_proxy()` filter removes `_...` and `has_...` keys only from the top-level `details` dictionary.

However:

- the pipeline stores the raw source in `proxy.details["_source"]`;
- revival stores a full `origin_proxy` model dump;
- chain hops are serialized with `Proxy.model_dump()`;
- `origin_config.details` is copied wholesale from the original proxy.

Thus `_source` can survive inside nested `chain[*].details` and `origin_config.details`, including subscription paths or tokens. This contradicts `docs/PUBLIC_LISTS_GEO_AUDIT.md`, which claims internal provenance keys are stripped from public serialization.

**Required:** recursively sanitize public structures through an explicit allowlist/schema, never copy arbitrary internal `details` into public artifacts, and add a regression test that plants secrets at every nesting depth and scans every generated public artifact.

- The Promise wrapper ignores `reject`.
- A panic can therefore be swallowed and the Promise resolved with an empty/nil result rather than a structured rejection.

This is exactly the failure documented in `docs/WASM_JS_BRIDGE_INTEROP_AUDIT.md`. The proposed reject-wrapper patch was not applied.

`tests/unit/test_wasm_panic_recovery.py` merely searches the Go source for the substring `recover()`. That substring existed in the defective implementation, so the test passes while proving nothing about Promise behavior.

**Required:** recover in the Promise goroutine, reject or resolve with a documented structured error exactly once, prevent double resolution, and execute the compiled WASM in a browser test that deliberately triggers the failure path.

### 5. Hysteria3 is not connected to normal pipeline ingestion

`parse_hysteria3` is exported from `configstream.parsers`, but `src/configstream/auto_detect.py` does not import or register it in:

- the scheme-to-parser map,
- fallback parsers,
- valid-scheme enforcement.

The pipeline calls `configstream.consumer.parse_config`, which forwards to `auto_detect_and_parse`. Consequently, normal source ingestion cannot parse `hy3://` or `hysteria3://` even though direct unit tests of `parse_hysteria3()` pass.

The alias is also absent from `_OUTPUT_PROTOCOL_ALIASES`, so `hy3` is not canonically normalized to `hysteria3` as claimed by `docs/protocol_matrix.json`.

**Required:** test the actual public ingestion entrypoint, not just the leaf parser. Add both schemes to auto-detection, fallback validation, canonical normalization, extraction/allowlists, frontend parsing where claimed, and protocol ordering where appropriate.

### 6. The new protocol parsers do not implement their own documented contracts

`docs/PARSER_EXTENSION_SPEC.md` specifies substantially richer behavior than the committed parsers.

For TUIC, the spec requires `cc_algo`, integer `max_idle_time`, integer `initial_max_streams`, and ALPN list semantics. The implementation only records `password`, `congestion_control`, and scalar `alpn`.

For Hysteria3, the spec requires `multi_port`, `obfs_v2`, `padding_len`, username/UUID mapping, and conditional rejection when an obfuscation mode requires a password. The implementation omits those fields and validations and leaves `uuid` empty.

The documents also disagree with each other: the extension specification advertises Sing-box and Clash export support for Hysteria3, while `docs/protocol_matrix.json` marks both exports false.

**Required:** establish one authoritative wire/field contract, implement it end-to-end, validate numeric/range/list fields, define malformed-input behavior, and regenerate all matrix/schema/wiki claims from that source of truth.

### 7. `GoBatchTester.test_custom_configs()` retains the unbounded IPC deadlock

The bridge audit explicitly scopes the bounded-drain remediation to both `test_batch()` and `test_custom_configs()`.

Only `test_batch()` now wraps `stdin.drain()` with a 15-second timeout. `test_custom_configs()` still acquires `_lock`, writes the payload, and awaits `proc.stdin.drain()` without any bound. A wedged daemon can still block this high-centrality bridge indefinitely while holding the process lock.

No new test exercises this method.

**Required:** use the same bounded write/drain policy for all IPC writers, clean pending futures, avoid holding the global lifecycle lock across a potentially slow drain, classify timeout/crash outcomes consistently, and test daemon restart/disable behavior for custom configs.

### 8. Internal source URLs can still leak through nested revived-proxy structures

The new `serialize_proxy()` filter removes `_...` and `has_...` keys only from the top-level `details` dictionary.

However:

- the pipeline stores the raw source in `proxy.details["_source"]`;
- revival stores a full `origin_proxy` model dump;
- chain hops are serialized with `Proxy.model_dump()`;
- `origin_config.details` is copied wholesale from the original proxy.

Thus `_source` can survive inside nested `chain[*].details` and `origin_config.details`, including subscription paths or tokens. This contradicts `docs/PUBLIC_LISTS_GEO_AUDIT.md`, which claims internal provenance keys are stripped from public serialization.

**Required:** recursively sanitize public structures through an explicit allowlist/schema, never copy arbitrary internal `details` into public artifacts, and add a regression test that plants secrets at every nesting depth and scans every generated public artifact.

## Documentation contradictions that must be reconciled

The audit corpus cannot currently serve as reliable evidence because several documents conflict with implementation or with each other:

- The parser extension spec and protocol matrix disagree on Hysteria3 export support.
- The public-list audit claims recursive provenance stripping that the serializer does not perform.
- The Go sidecar audit says pipe consumption eliminates deadlocks, while the bridge audit correctly identifies an unbounded `drain()` path that still exists.
- The repo-wide slop audit says `RateLimitError` and `parse_retry_after` should be removed; the new slop tests explicitly require and test those symbols.
- The WASM audit says existing recovery is defective; the new test treats the mere presence of that defective recovery as success.
- The implementation plans retain unchecked `- [ ]` steps but are shipped alongside a PR claiming execution is complete.

Audit reports should distinguish **observed current state**, **accepted remediation**, **implemented change**, **verified evidence**, and **future recommendation**. Those categories are currently blended together.
