# Output File Variations

This document provides a detailed reference for all output files generated by the ConfigStream pipeline.

## Output Categories

### 1. Standard Outputs
Core files generated on every run.
- `singbox.json`: Sing-box JSON node subscription; supported outbounds/endpoints update as independent entries.
- `nekobox.json`: NekoBox multi-node subscription (minimal object with standalone `outbounds` and modern `endpoints`).
- `xray.json`: Xray/V2Ray outbounds-only node subscription.
- `clash.yaml`: Mihomo/Clash proxies-only node subscription.
- `singbox-profile.json`, `xray-profile.json`, `clash-profile.yaml`: separate complete runnable client profiles.
- `proxies.json`: ConfigStream API dataset containing an array of proxy records.
- `base64.txt`: Base64 of the newline-delimited share-link subscription.

### 2. DNS-Safe Outputs (`-dns-safe`)
Variants using pre-resolved IP addresses to bypass DNS poisoning.
- `singbox-dns-safe.json`
- `nekobox-dns-safe.json`
- `base64-dns-safe.txt`

### 3. DNS-Hardened Outputs (`-dns-hardened`)
Variants that prefer IPs but keep hostnames as fallbacks, embedding DoH/DoT/DoQ resolvers.
- `singbox-dns-hardened.json`
- `nekobox-dns-hardened.json`
- `clash-dns-hardened.yaml`

## ⛓️ Chain Types Included
All chain-enabled outputs (`singbox-chains.json`) include:
- **Washed Chains**: Working proxies wrapped in WARP.
- **Revived Chains**: Previously failing proxies resurrected via WARP/Vwarp.
- **Shielded Chains (Gold)**: Client → WARP → Proxy routing.
- **Smart Chains**: Optimized multi-hop paths.

## 🚀 Evasion Features
- **uTLS Fingerprinting**: Chrome/Firefox/Safari mimicry.
- **Multiplexing**: HTTP/2 multiplexing with padding.
- **ALPN Rotation**: Deterministic protocol variation.

See [README.md](../../README.md) for the full Output Matrix.

## Payload Shape and Import Compatibility

JSON syntax alone does not make two artifacts interchangeable. Native clients
expect one complete root configuration object; ConfigStream's API artifacts use
arrays so the frontend and downstream tools can inspect individual records.

| Artifact | Top-level shape | Intended consumer | Subscription behavior |
|---|---|---|---|
| `proxies.json`, `api/proxies` | Array of ConfigStream proxy records | Frontend, analytics, API clients | Not a subscription |
| `countries/*.list.json`, `protocols/*.list.json` | Array of ConfigStream proxy records | Filtering and API clients | Not a native-client subscription |
| `singbox*.json` (excluding `*-profile`, VPN, chain files) | Minimal object with independent `outbounds` / `endpoints` | NekoBox/v2rayN/Hiddify-compatible JSON subscription importers | Expands supported proxies as separate entries |
| `xray.json` | Object containing independent `outbounds` only | v2rayN/NekoBox-compatible Xray/V2Ray JSON importers | Expands supported outbounds as separate entries |
| `clash*.yaml` (excluding `*-profile`) | YAML with `proxies` only | Mihomo/Clash-compatible subscription importers | Updates the independent proxy list |
| `singbox-profile*.json`, `xray-profile.json`, `clash-profile*.yaml` | Complete runnable client configurations | Native cores / full-profile import | One explicit full profile; not the subscription URL |
| `chains*.json`, `singbox-vpn*.json`, `countries/*.json`, `protocols/*.json` | Complete sing-box objects | Full-profile use cases | Full configurations |
| `proxies*.txt` | Newline-delimited share URIs | URI-aware subscription clients | Separate entries |
| `base64*.txt` | Base64 encoding of corresponding `proxies*.txt` | Base64 subscription clients | Separate entries |

JSON shape alone does not determine semantics. The canonical Sing-box/Xray subscription files deliberately omit profile-level routing, DNS, inbound, selector/helper, and dependency state so subscription updates expand independent nodes. Those richer semantics remain available only in the explicit `*-profile` artifacts.

The API-array document shape is published as `schema/proxy-list.schema.json`,
which references `schema/proxy.schema.json` for each item. The release pipeline
validates the complete native configurations with the pinned
native `sing-box check`, `xray run -test`, and `mihomo -t` commands. The API
arrays are instead validated item-by-item against `schema/proxy.schema.json`.
