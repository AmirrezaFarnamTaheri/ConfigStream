# Sing-box Configuration Guide

## Overview
Sing-box uses a modular JSON configuration format. It is more structured than V2Ray and more flexible than Clash. This guide unpacks the key sections generated by ConfigStream, including chain configurations used by the Laboratory page.

## 1. Inbounds (Entry Points)
How traffic enters the proxy core.
*   **Mixed (HTTP/SOCKS):** Default inbound. Apps connect to this port as an HTTP or SOCKS5 proxy.
    ```json
    {
      "type": "mixed",
      "tag": "mixed-in",
      "listen": "127.0.0.1",
      "listen_port": 2080
    }
    ```
*   **TUN (Transparent Proxy):** Used in "Tank" mode. Creates a virtual network interface that captures all system traffic.
    ```json
    {
      "type": "tun",
      "tag": "tun-in",
      "inet4_address": "172.19.0.1/30",
      "auto_route": true,
      "strict_route": true
    }
    ```
*   **Note:** The Lab chain builder uses `mixed` inbound on port 2080 by default. You can change the port in the exported config.

## 2. Outbounds (Exit Points)
Where traffic goes. This is where the proxy servers (VLESS, WireGuard, etc.) and chain layers are defined.
*   **Selector:** Allows the user to manually choose a node from a list.
*   **URL Test:** Automatically chooses the fastest node based on latency pings.
*   **Direct:** Traffic goes straight to the internet (bypassing proxies). Used for domestic/local traffic.
*   **Block:** Traffic is dropped (ads, tracking, malware domains).
*   **Proxy Outbounds:** VLESS, VMess, Trojan, Shadowsocks, Hysteria2, TUIC, WireGuard, SOCKS, HTTP — each with protocol-specific fields.

### The `detour` Field (Chaining)
The `detour` field is how sing-box chains outbounds together. When outbound A has `"detour": "B"`, traffic flows through A first, then B routes it to the network.

```
Traffic → Outbound A (detour: "B") → Outbound B (detour: "C") → Outbound C → Internet
```

This is the core mechanism behind all ConfigStream chain strategies (WARP shielding, proxy cascade, intranet relay).

## 3. Route (Routing Rules)
The "Brain" of the config. It decides which inbound packet goes to which outbound.
*   **GeoIP Rules:** "If IP is in Iran/China, go Direct." Prevents breaking local services.
*   **Geosite Rules:** "If domain is `category-ads`, go Block." Ad blocking without a separate tool.
*   **Process Name:** "If app is Discord or Telegram, go Proxy." Per-app routing.
*   **Domain Suffix:** "If domain ends with `.ir`, go Direct." Domestic bypass.
*   **IP CIDR:** "If destination is `192.168.0.0/16`, go Direct." LAN traffic bypass.
*   **Default:** Everything else goes to the proxy selector or URL test group.

### ConfigStream Routing Profiles
*   **Sniper (Default):** Only routes blocked/foreign traffic through the proxy. Local traffic goes direct.
*   **Tank:** Routes everything through the proxy (full VPN mode). Use on hostile networks.

## 4. DNS (Domain Name System)
Sing-box has a built-in DNS server to prevent DNS leaks.
*   **Remote DNS:** Encrypted DNS (DoH/DoT) routed through the proxy (e.g., `https://8.8.8.8/dns-query`). Ensures your ISP cannot see DNS queries.
*   **Local DNS:** ISP DNS for local geo-routing (domestic domains resolve correctly).
*   **FakeIP:** Returns a fake IP range (`198.18.0.0/15`) to force traffic into the TUN interface immediately. Used in Tank mode to eliminate DNS queries entirely.

### DNS Profiles in ConfigStream
*   **Standard:** Uses hostnames as-is. DNS resolved by the proxy server.
*   **DNS-Safe:** All hostnames pre-resolved to IPs. Bypasses DNS poisoning completely. SNI/Host headers preserved.
*   **DNS-Hardened:** Embeds multiple DoH/DoT/DoQ resolvers with fallback ordering. IPs preferred when available.

## 5. Chain Configuration Examples

### Example 1: WARP Shielded Chain
Your ISP sees a connection to Cloudflare. Cloudflare routes to your proxy.
```json
{
  "inbounds": [
    { "type": "mixed", "tag": "mixed-in", "listen": "127.0.0.1", "listen_port": 2080 }
  ],
  "outbounds": [
    {
      "type": "vless", "tag": "proxy-out",
      "server": "example.com", "server_port": 443,
      "uuid": "your-uuid",
      "tls": { "enabled": true, "server_name": "example.com" },
      "detour": "warp-out"
    },
    {
      "type": "wireguard", "tag": "warp-out",
      "server": "162.159.192.1", "server_port": 2408,
      "local_address": ["172.16.0.2/32"],
      "private_key": "...",
      "peer_public_key": "bmXOC+F1FxEMF9dyiK2H5/1SUtzH0JuVo51h2wPfgyo=",
      "mtu": 1280
    },
    { "type": "direct", "tag": "direct" },
    { "type": "block", "tag": "block" }
  ],
  "route": {
    "rules": [
      { "geoip": ["private"], "outbound": "direct" }
    ],
    "final": "proxy-out"
  }
}
```

### Example 2: Proxy Cascade (No WARP)
Chain through a local Psiphon SOCKS5 proxy to reach a VLESS server.
```json
{
  "outbounds": [
    {
      "type": "vless", "tag": "proxy-out",
      "server": "example.com", "server_port": 443,
      "uuid": "your-uuid",
      "tls": { "enabled": true, "server_name": "example.com" },
      "detour": "cascade-layer1"
    },
    {
      "type": "socks", "tag": "cascade-layer1",
      "server": "127.0.0.1", "server_port": 1080,
      "version": "5"
    }
  ]
}
```

### Example 3: Relay Hop
Route through any intermediate proxy (LAN, remote, or pipeline output).
```json
{
  "outbounds": [
    {
      "type": "trojan", "tag": "proxy-out",
      "server": "example.com", "server_port": 443,
      "password": "your-password",
      "tls": { "enabled": true, "server_name": "example.com" },
      "detour": "lan-relay"
    },
    {
      "type": "http", "tag": "lan-relay",
      "server": "192.168.1.50", "server_port": 3128
    }
  ]
}
```

### Example 4: Double WARP
Two layers of WARP encryption for maximum obfuscation.
```json
{
  "outbounds": [
    {
      "type": "vless", "tag": "proxy-out",
      "server": "example.com", "server_port": 443,
      "uuid": "your-uuid",
      "detour": "warp-inner"
    },
    {
      "type": "wireguard", "tag": "warp-inner",
      "server": "162.159.192.1", "server_port": 2408,
      "private_key": "...", "peer_public_key": "bmXOC+...",
      "mtu": 1280,
      "detour": "warp-outer"
    },
    {
      "type": "wireguard", "tag": "warp-outer",
      "server": "188.114.98.224", "server_port": 854,
      "private_key": "...", "peer_public_key": "bmXOC+...",
      "mtu": 1280
    }
  ]
}
```

## 6. Evasion Options
These fields can be added to proxy outbounds to evade DPI:

### uTLS Fingerprint
Makes the TLS handshake look like a specific browser.
```json
"tls": {
  "enabled": true,
  "utls": { "enabled": true, "fingerprint": "chrome" }
}
```
Supported fingerprints: `chrome`, `firefox`, `safari`, `ios`, `android`, `edge`, `random`.

### ALPN (Application-Layer Protocol Negotiation)
```json
"tls": { "alpn": ["h2", "http/1.1"] }
```

### Multiplexing with Padding
Hides packet size patterns by multiplexing streams and adding random padding.
```json
"multiplex": {
  "enabled": true,
  "protocol": "h2mux",
  "max_connections": 4,
  "padding": true
}
```

### TLS Fragmentation
Splits TLS ClientHello into small fragments to evade stateless DPI. Configured at the transport level (not in sing-box directly — used by the Lab's fragment chain strategy).

## 7. Xray/V2Ray Chain Compatibility
Sing-box chains use `detour` to link outbounds. Xray/V2Ray use `proxySettings.tag` for the same purpose:

| Core | Chain Field | Example |
|---|---|---|
| **Sing-box** | `"detour": "warp-out"` | On the outbound that should route through another |
| **Xray/V2Ray** | `"proxySettings": { "tag": "warp-out" }` | Same semantics, different field name |
| **Clash/Mihomo** | `dialer-proxy: "warp"` | YAML field on the proxy entry |

The Lab's export function automatically converts between these formats.

**Note:** Xray-core supports WireGuard natively using `secretKey` + `peers[].publicKey` format. The Lab export automatically converts between sing-box and Xray field names.

## 8. Lab Integration
The ConfigStream Laboratory page generates complete sing-box JSON configs with all the above features. The flow:
1.  **Step 1:** Parse your proxy URI → creates the proxy outbound.
2.  **Step 2:** Find clean IPs → configures the WARP outbound endpoint.
3.  **Step 3:** Build chain → links outbounds with `detour` fields (7 strategies available: WARP, Double WARP, WARP+Psiphon, Relay Chain, TLS Fragment, CDN Worker, Custom).
4.  **Step 4:** Test → verifies the chain works end-to-end.
5.  **Step 5:** Export → Sing-box JSON, Clash YAML, Xray JSON, URI, QR code, Python script, Bash script.

### Using Pipeline Proxies
The Lab page can fetch pre-tested proxies from ConfigStream's pipeline output (`output/base64.txt`). Click "Load Pre-Tested Proxies" at Step 1 to browse verified proxies grouped by protocol.
