# Sing-box Configuration Guide

## Overview
Sing-box uses a modular JSON configuration format. It is more structured than V2Ray and more flexible than Clash. This guide unpacks the key sections generated by ConfigStream.

## 1. Inbounds (Entry Points)
How traffic enters the proxy core.
*   **Mixed (HTTP/SOCKS):** Default inbound.
    ```json
    {
      "type": "mixed",
      "tag": "mixed-in",
      "listen": "127.0.0.1",
      "listen_port": 2080
    }
    ```
*   **TUN (Transparent Proxy):** Used in "Tank" mode. Creates a virtual network interface.
    ```json
    {
      "type": "tun",
      "tag": "tun-in",
      "inet4_address": "172.19.0.1/30",
      "auto_route": true,
      "strict_route": true
    }
    ```

## 2. Outbounds (Exit Points)
Where traffic goes. This is where the proxy servers (VLESS, WireGuard) are defined.
*   **Selector:** Allows the user to manually choose a node.
*   **URL Test:** Automatically chooses the fastest node (latency-based).
*   **Direct:** Traffic goes straight to the internet (bypassing proxies).
*   **Block:** Traffic is dropped (Ads, Tracking).

## 3. Route (Routing Rules)
The "Brain" of the config. It decides which Inbound packet goes to which Outbound.
*   **GeoIP Rules:** "If IP is CN, go Direct."
*   **Geosite Rules:** "If domain is category-ads, go Block."
*   **Process Name:** "If app is Discord, go Proxy."

## 4. DNS (Domain Name System)
Sing-box has a built-in DNS server to prevent DNS Leaks.
*   **Remote DNS:** Encrypted DNS (DoH/DoT) routed through the proxy (e.g., `8.8.8.8`).
*   **Local DNS:** ISP DNS for local geo-routing.
*   **FakeIP:** Returns a fake IP range to force traffic into the TUN interface immediately (used in Tank mode).
